# ADR-0011: サーバ側で import ワークフローを実行する

## 背景と課題

ADR-0006 は local-repo を各開発者の PC に置く前提へ変更したが、初期取り込みや追加取り込みでは対象サーバ上の多数のファイルを local-repo に集約する。PC 上で `import` すると、対象サーバ間では LAN で取得できる内容まで WAN の SSH 経由で転送することになる。従来の実運用では1台目で import し、2、3台目にある共通コンテンツは1台目への symlink で共有していた。

## 判断の基準

- WAN を通る転送量を最小化する
- サーバ単位で異なるファイルを管理できる
- 従来の symlink による共通コンテンツ配布を維持できる
- import の途中状態から回復できる
- 利用者が同期・取得・pushの各段階を選び分けなくてよい

## 検討した選択肢

| 案 | 概要 | 採らなかった理由 |
|---|---|---|
| A | 開発者 PC から全ホストを import する | 全コンテンツが WAN を通り、初期取り込みの負荷が大きい |
| B | 1台目で import ワークフローを実行し、他ホストは LAN SSH で取得する | 採用 |
| C | repository 上にファイルの所有ホストを定義する | サーバ上のファイルをサーバ単位で取り込む目的には不要な管理モデルとなる |
| D | コマンドを自動的に1台目へ転送して実行する | 実行主体が見えにくくなり、認証・失敗時の回復も複雑になる |
| E | 失敗した段階に応じて単独の `sync` / `push` で復旧する | 利用者向けコマンドと段階判断が増える |
| F | 原因を解消して同じ `import` を再実行する | 採用 |

## 決定

採用: **案 B と案 F**。初期取り込みと追加取り込みは1台目のサーバに置いた local-repo で行い、1台目自身はローカル、他の有効なホストは LAN SSH 経由で取得する。repository 上のコンテンツ所有関係、コマンドの自動転送、段階別の復旧コマンドは導入しない。

### 詳細

- `import` を次の一連の処理を行う標準コマンドとする。
  1. 既存 repository では指定ブランチと同期する。初回 commit 前は省略する。
  2. すべての有効なホストから設定対象を取得する。
  3. 変更を commit し、指定ブランチへ push する。
- 初回 commit 前は、`init` が生成し利用者が編集した `isucontinuous.yaml` と取得ファイルを最初の commit に含める。
- 既存 repository では、開始時に作業ツリーが clean でなければ拒否する。
- 一つの local-repo ロックを全工程で保持する。ホストロックはファイル取得中だけ保持する。
- ファイル取得に失敗した場合は commit/push せず、取得済みの変更を作業ツリーに残す。push に失敗した場合はローカル commit を残す。
- 失敗原因を解消し、ホストロックが残っていれば `release` した後、同じ `import` を再実行する。ホスト上の内容が同じなら追加 commit は作らず、push に失敗して残ったローカル commit も再実行で push する。
- 同期と push は `import` の内部フェーズとし、単独の `sync` / `push` コマンドは提供しない。
- import は deploy とは異なり、local-repo の出力先パスにある symlink を辿らない。ホスト直下の symlink はリモート読み込み前にそのホストを skip し、より深い symlink は影響するファイルまたは subtree を skip して警告する。broken symlink や repository 外を指す symlink も同様に扱う。
- 対象サーバ側の取得元 symlink は、従来どおり import 対象外とする。
- deploy は repository 内の symlink を従来どおり辿る。これにより、2、3台目の共通コンテンツを1台目のディレクトリへ向けた symlink として管理できる。
- import 対象を探索して `deploy.targets` を提案する責務は skill に置く。境界は ADR-0009 に定める。

## 各案の評価

案 B は1台目から他ホストへの LAN 転送だけで取り込みを完結できる。一方、開発者 PC の MCP/CLI から import を直接実行する構成にはならず、利用者が実行場所を選ぶ必要がある。

## 影響

- 良い影響: WAN 越しに全コンテンツをダウンロードせず、従来の symlink 運用を維持できる。
- 悪い影響・トレードオフ: 1台目に isucontinuous と local-repo を用意し、import だけはそこで実行する必要がある。
- 他の ADR・コードへの影響: ADR-0006 を置き換える。CLI の import、local-repo の書き込み、結果型、ドキュメントを変更する。
