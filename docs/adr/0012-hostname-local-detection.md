# ADR-0012: 設定ホスト名との一致でローカル実行を自動判定する

## 背景と課題

サーバ1台目で import を実行する場合、自ホストへのアクセスまで SSH にする必要はない。ADR-0004 は開発者 PC への誤 deploy を防ぐため `local: true` のときだけローカル実行すると決めたが、同じ設定を開発者 PC とサーバの両方から使うには実行場所ごとの書き換えが必要になる。

## 判断の基準

- 同じ `isucontinuous.yaml` を開発者 PC と対象サーバで利用できる
- 開発者 PC を誤って対象ホストとして扱わない
- repository のディレクトリ名や表示名を実行場所によって変えない

## 検討した選択肢

| 案 | 概要 | 採らなかった理由 |
|---|---|---|
| A | `local: true` のみローカルとする | 実行場所ごとに設定変更が必要になる |
| B | `os.Hostname()` と展開後の `host` が完全一致すればローカルとする | 採用 |
| C | short name、FQDN、IP address も解決して比較する | 暗黙の一致条件が増え、誤判定しやすい |
| D | 接続失敗時にローカルへ fallback する | 接続障害を誤ってローカル実行へ変える危険がある |

## 決定

採用: **案 B**。設定読み込み時に `os.Hostname()` とテンプレート展開後の `host` を文字列で完全一致比較し、一致したホストをローカル実行とする。

### 詳細

- `local: true` は従来どおり明示的にローカル実行を強制する。
- `local: false` と未指定は区別せず、hostname の一致による自動判定を許可する。
- 比較は完全一致だけとし、DNS 解決、IP address 比較、short name/FQDN の正規化はしない。
- hostname の取得に失敗した場合は設定読み込みを失敗させる。
- `name` は変更しない。省略時に `host` を使う規則も維持し、ローカル判定によって `localhost` へ置き換えない。
- `host: localhost` / `127.0.0.1` に `local: true` を要求する既存の検証は維持する。

## 各案の評価

完全一致は、1台目の設定をその実ホスト名にしておけばサーバ上だけでローカル実行となり、PC 上では SSH のままになる。host alias や FQDN の差は自動吸収しないため、必要なら `local: true` を明示する。

## 影響

- 良い影響: 同一設定を PC とサーバで共有し、1台目への不要な SSH を避けられる。
- 悪い影響・トレードオフ: OS の hostname と設定値が表記上異なる場合は自動判定されない。
- 他の ADR・コードへの影響: ADR-0004 を置き換え、設定読み込みとテストを変更する。
