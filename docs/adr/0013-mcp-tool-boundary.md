# ADR-0013: MCP は開発ループで使うツールだけを公開する

## 背景と課題

ADR-0001 は CLI と MCP のサブコマンドを1対1にし、初期化や repository 操作も含む11ツールを公開した。サーバ側で行う import ワークフローと、開発者 PC で LLM が回す開発ループでは実行場所と利用頻度が異なる。repository を初期化・同期・commit/push する操作を MCP に公開すると、LLM が誤った実行場所や意図しないタイミングで repository を変更できる範囲が広がる。

## 判断の基準

- MCP のツール面を LLM の開発ループに必要な操作へ限定する
- 初期構築・取り込み・復旧は人間が実行場所と状態を確認して行える
- CLI からの運用・復旧能力は失わない

## 検討した選択肢

| 案 | 概要 | 採らなかった理由 |
|---|---|---|
| A | 全 CLI サブコマンドを MCP に公開する | repository 変更操作まで LLM に公開する必要がない |
| B | 開発ループに必要な7ツールだけを MCP に公開する | 採用 |
| C | MCP 自体を廃止する | deploy・計測・結果取得を LLM から行う目的を満たさない |

## 決定

採用: **案 B**。MCP は `setup`、`deploy`、`diff`、`status`、`profiling`、`afterbench`、`release` の7ツールだけを公開する。

### 詳細

- `init`、`sync`、`import`、`push` は CLI 専用とし、MCP tool として登録しない。
- 非公開にしたコマンドの usecase や CLI は削除しない。
- MCP と CLI の意味を揃える原則は、双方に公開されるコマンドに対して維持する。
- import 対象の探索と設定案の作成は将来の skill が担当するが、設定編集、import、push の自動実行は skill の責務に含めない。

## 各案の評価

案 B は通常の開発ループを維持したまま、実行場所を意識すべき repository 操作を明示的な CLI 実行へ限定する。CLI と MCP の完全な1対1対応は失われる。

## 影響

- 良い影響: LLM に公開する破壊的・状態変更的な操作面が狭くなる。
- 悪い影響・トレードオフ: MCP クライアントだけでは初期構築と import の全工程を完了できない。
- 他の ADR・コードへの影響: ADR-0001 を置き換え、MCP の tool 登録、runner、テスト、文書を変更する。
