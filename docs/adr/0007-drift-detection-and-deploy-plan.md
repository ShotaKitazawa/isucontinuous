# ADR-0007: drift 検出とデプロイ計画

## 背景と課題

- サーバ上のファイルが直接編集されても、`deploy` は気づかずに上書きする。
- 「新しい revision とサーバを比べる」方法では、デプロイすれば必ず差が出るため、drift を検出できない。意味のある基準は**前回デプロイした内容**である。
- `Deployer.Deploy` (`pkg/usecases/deploy/deploy.go`) は、走査 (コピー元とコピー先の対応づけ、symlink の辿り) と実行が一体になっている。
- 実行も効率が悪い。ファイルごとに `test -d` を SSH で実行し、SFTP のクライアントも毎回作る (`pkg/shell/ssh.go` の `Deploy`)。サーバ間の LAN ではなく PC からの WAN 越しになるため、影響が大きい。
- `Deploy` は SFTP で内容だけを書く。ファイルモードは設定しない。また、サーバにあって repo にないファイルは削除しない。

## 検討した選択肢

| 案 | 却下理由 |
|---|---|
| 新しい revision とサーバを比べて drift とする | デプロイすれば必ず差が出るため、検出にならない |
| モードも比較する | `deploy` がモードを設定しないため、意味がない |
| `deploy --force` を drift の無視にも使う | ロックの強制取得と意味が重なり、意図しない上書きを招く |
| 検査を `deploy` の前に別コマンドで要求する | 実行し忘れると検査されない。ロック取得後に自動で行うほうが確実 |

## 決定

### 計画と実行の分離

`Deploy` を、**計画** (コピー元とコピー先の対応づけ。symlink の辿りを含む) と**実行**に分ける。`diff` と dry-run は計画だけで実現する。

### `diff [--revision R]`

- サーバ上のファイルと、revision R の内容を比較する。
- `R` を省略すると、そのホストで**最後にデプロイした revision** と比較する (drift の検出)。指定すると、「deploy すると何が変わるか」の確認になる。
- 比較するのは**内容のみ**。モードは比較しない (`deploy` がモードを設定しないため、モードの差は `deploy` が壊すものではない)。
- revision の内容は、作業ツリーを動かさずに `git show <rev>:<path>` で取る。
- 出力は、変更・欠落ファイルの一覧が既定。差分の本文は指定したときだけ出す。
- サーバにあって repo にないファイルは対象外。

### deploy の事前検査

- `deploy` は、ロック取得後に `diff` (R を省略) を実行し、差があればエラーにする。無視する場合は `--ignore-drift` を指定する (ロックの `--force` とは別の名前にする)。
- 最後にデプロイした revision が記録されていない初回は、検査を省略する。
- 既存の `deploy --force` (`.revision` のガード) は、ロックに置き換わるため廃止する。

### 最後にデプロイした revision

- ホスト上に、ロックとは**別のファイル**で保存する (ロックは `afterbench` で解放されるため)。
- 保存する revision は、解決したコミットハッシュ ([0006](0006-local-repo-operation.md))。

### 実行の効率化

- 実行時は、**変更のあるファイルだけ**を転送する。
- SFTP のクライアントを使い回し、ファイルごとの `test -d` をやめる。

## 影響

- 計画を切り出すことで、`diff` のためにシンボリックリンクの辿りを再実装せずに済む。
- 初回のデプロイは検査されない。
